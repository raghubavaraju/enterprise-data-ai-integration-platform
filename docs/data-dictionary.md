## Conventions

| Convention | Rule |
|---|---|
| Naming | `SCREAMING_SNAKE_CASE`; layer prefix only in RAW and STAGING |
| Business key | The source's natural key, verbatim, suffixed `_BK` |
| Surrogate key | `MD5` of the business key (+ effective date for SCD2), suffixed `_SK` |
| Audit columns | `_SRC_SYSTEM`, `_SRC_FILE`, `_INGESTED_AT`, `_BATCH_ID`, `_CORRELATION_ID`, `_ROW_HASH`, `_LOADED_AT` |
| Money | `NUMBER(18,2)` with an explicit currency column - never a bare float |
| Time | `TIMESTAMP_NTZ`, UTC everywhere |
| Reserved words | `ORDER` is reserved, so the order entity is `SALES_ORDER` |

## Coverage

27 of 914 columns carry a **curated** business definition, owner and classification, agreed with the domain owner. The rest are audit columns, structural keys, and RAW/STAGING copies whose classification is **inferred** from the column name and marked *(inferred)* in the tables above.

The distinction matters. A dictionary that presents a guess with the same confidence as a curated entry is worse than one that admits the gap - and the RAW copy of an e-mail address is as sensitive as the CORE copy, whether or not anyone has written it down yet.

Every column the platform classifies as PII names a masking policy; CI fails if one does not.
